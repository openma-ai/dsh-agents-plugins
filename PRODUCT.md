# Product

## Register

product

## Users

DSH users and plugin authors who need to discover, import, inspect, enable, and run Codex, Claude Code, Pi, and portable Agent Plugins from Web or TUI without learning a second plugin lifecycle.

## Product Purpose

Bridge foreign agent-plugin ecosystems into DSH as explicit, independently managed capability rows. Success means users can reuse installed plugins and marketplaces through native DSH surfaces while preserving clear ownership, reversibility, and strict compatibility boundaries.

## Brand Personality

Native, compact, trustworthy. The bridge should feel like a built-in DSH capability rather than a separate branded application.

## Anti-references

- Opaque universal plugin runtimes that hide component ownership.
- Decorative dashboards, nested card grids, or custom chrome that competes with the DSH host.
- Dense data rendered as unbounded button clouds, clipped text, horizontal overflow, or modal-within-modal layouts.
- Guessed compatibility behavior or silent fallbacks for unknown foreign formats.

## Design Principles

- Everything is a plugin: expose each capability through the smallest reversible DSH row.
- Follow the host: reuse DSH typography, tokens, controls, and interaction conventions.
- Progressive density: summarize first, then reveal large catalogs through search and bounded scrolling.
- Make state legible: discovery, import, installation, enablement, requirements, and diagnostics must remain distinct.
- Fail explicitly: unsupported shapes remain visible diagnostics instead of being guessed or silently discarded.

## Accessibility & Inclusion

Target WCAG 2.1 AA for text and controls. Preserve keyboard navigation, visible focus, reduced-motion preferences, readable status text independent of color, and responsive layouts that do not require horizontal scrolling.
